# Methodology

## Purpose

AI Enablement Radar monitors authoritative sources and translates material changes into adoption-oriented signals. It is an intelligence aid, not a substitute for reviewing the original announcement.

## Source policy

Sources must be first-party product, engineering, research, or release channels. Each signal retains its canonical source URL and publication timestamp. Sources are listed in `config/sources.json`.

## Automated pipeline

The daily workflow:

1. Fetches configured feeds.
2. Records success, failure, and response metadata.
3. Deduplicates items by source and canonical URL.
4. Scores titles and summaries against transparent keyword rules.
5. Assigns domain, audience, enablement lens, adoption risk, and suggested response.
6. Publishes a dated monitoring record and machine-readable data.
7. Validates required fields, URLs, duplicates, and source attribution.

## Interpretation boundaries

Recommended responses are deterministic prompts for professional judgment. They are not claims made by the source publisher. The system never invents quotations or treats an inferred implication as a publisher statement.

## Automation disclosure

Daily reports and structured signal records are generated by the repository workflow. Human-authored field notes are explicitly labelled. Scheduled commits are part of the maintained data pipeline and are not represented as hand-written daily coding.

## Quality controls

- First-party sources only
- Canonical links required
- Duplicate detection
- Schema validation
- Transparent rules
- Automated-source labelling
- No backdated records
- No fabricated “news” when no material change is found
